# mindmap_undo：协作思维导图撤销库

纯 Python、零依赖的进程内库。多个用户交错编辑同一张思维导图时，
每个用户只能撤销/重做**自己的**操作，且不会抹掉他人后续的独立修改。
数据仅保存在进程内存中，不涉及任何外部服务、端口或持久化。

## 业务规则要点

- 节点集合固定：每个节点有唯一标识、标题和父节点；根固定，根深度为 0，最大深度 15。
- 批次整体生效：以全部改动后的最终树判断合法性，不因逐项过渡状态拒绝最终合法的批次。
- 撤销/重做按人进行：目标是本人最近提交（撤销）或最近撤销（重做）的批次；
  目标冲突时整体失败，不跳过、不产生部分回退、不改变回退次序。
- 覆盖关系按字段区分：同值写入也算新编辑；标题与父节点分别判断。
  后来编辑被撤销后，该字段原先生效的编辑自动重新生效。
- 撤销/重做同样要求整树合法（不成环、不脱离根、深度 ≤ 15），否则整体失败。
- 每图仅最近 200 个成功批次可成为撤销/重做目标，按首次提交顺序淘汰；
  淘汰不改变当前导图，较新批次仍可撤销到被淘汰批次留下的效果。

## 快速开始

```python
from mindmap_undo import MindMap, NodePatch

# 初始导图：{节点标识: (标题, 父节点标识)}，根的父节点为 None
m = MindMap("R", {
    "R": ("root", None),
    "A": ("a", "R"),
    "B": ("b", "A"),
})

# 提交批次：一个批次可改多个节点的标题/父节点，未列出的字段保持原样
m.submit("alice", {"A": NodePatch(title="a2"), "B": NodePatch(parent_id="R")})

# 撤销 / 重做本人的操作；返回 False 表示失败且无任何变化
m.undo("alice")
m.redo("alice")

# 读取当前导图：{节点标识: NodeState(node_id, title, parent_id, depth)}
snap = m.snapshot()
print(snap["A"].title, snap["A"].parent_id, snap["A"].depth)
```

## API

- `MindMap(root_id, nodes)`：以初始合法导图创建实例；非法初始图抛 `InvalidTreeError`。
- `submit(user_id, changes) -> int`：提交批次，返回批次号。
  `changes` 为 `{节点标识: NodePatch(title=..., parent_id=...)}`，
  字段为 `None` 表示不修改。批次非法时抛 `InvalidTreeError` / `UnknownNodeError`，
  且不产生任何变化。
- `undo(user_id) -> bool` / `redo(user_id) -> bool`：
  成功返回 `True`；无目标、字段被他人覆盖、或回退后树非法时返回 `False`，
  且字段、回退次序、历史窗口均不变。
- `snapshot() -> dict[str, NodeState]`：当前完整导图（含各节点深度）。

## 运行测试

```bash
python3 -m unittest discover -s tests -v
```

测试覆盖：同值覆盖阻挡/解除阻挡撤销、失败批次无部分回退、整批合法但逐项
过渡成环、同事改挂导致撤销成环、深度 15 限制、第 201 批淘汰、重做分支保留、
与独立参考模型逐步对比完整树，以及 10 万次单字段提交的常驻内存检查
（实测第 1 万次到第 10 万次之间增长约 5 MiB，远低于 32 MiB 上限）。

## 实现说明

- 每个字段（节点 × 标题/父节点）维护一条按提交顺序的编辑链，当前生效编辑为
  链尾最近一个所属批次仍生效的编辑；撤销/重做只是切换批次的生效标记。
- 撤销要求目标批次写过的所有字段当前生效编辑仍是该批次；重做要求这些字段
  仍对应上次撤销恢复出的编辑（初始状态视为固定来源）。
- 历史窗口淘汰时回收字段编辑链：已撤销的淘汰批次编辑直接移除；仍生效的淘汰
  批次编辑成为永久锚点，其之前的编辑不可能再生效，一并回收，因此长序列提交
  的内存占用有界。
